# 顶会架构图视觉语法

会议是参考图来源，不是统一模板。以下规则按真实参考和当前方法调整。

| 方法关系 | 构图方向 | 需要解释的机制 |
| --- | --- | --- |
| 多模态融合 | 并行输入 → 对齐/交互 → 汇合 | 哪些模态产生哪些 token，在哪里交互 |
| 编码器—解码器 | 分区、尺度递进、外侧跳连 | 特征尺度、瓶颈和跨层连接 |
| Transformer | 主干概览配机制放大框 | Q/K/V 来源、注意力、残差、归一化 |
| 检索与记忆 | 主干和记忆旁路 | 查询来源、读写路径、检索结果注入位置 |
| 训练与推理不同 | 公共主干和训练分支 | 损失监督对象、冻结与可训练模块 |
| 多尺度视觉 | 金字塔、张量平面、跨尺度融合 | 分辨率和通道变化必须有真实依据 |

## 选参考并写 style-card.md

不要只按内容关键词。比较拓扑、分支汇合、嵌套、机制放大框、照片与符号比例、颜色含义，剔除叙事不兼容的图。

```text
References: 论文 ID、链接、视觉用途
Topology: 主路径、旁路、关键汇合和阅读顺序
Panels: 每块解释什么、比例与层级
Vocabulary: token、张量、矩阵、算子、注释
Palette: background / ink / visual / text / memory / output
Type scale: section / module / label / note
Strokes: module / primary / secondary / train-only
Density: 实际可见的元素与嵌套层级，不凭空计数
Scientific source: 对应用户方法或代码位置
```

## 设计规则

- 白底、细深灰边线、少量语义色。同一角色同色，不给所有方框随机上色。
- 主路径直线或正交走线，外侧预留跳连/反馈通道，箭头不穿文字。
- token 用小矩形序列，张量用叠片，注意力可用矩阵，尺度变化用金字塔；不要只画写着 features 的空框。
- 模块内部有模块名、子结构和必要符号；只增加解释机制需要的细节。
- 创新机制多留空间或用放大框。没有依据时不要加性能图、对比胜出区、虚假实验数值。
- 克制使用外框、阴影、渐变、厚边和大标题。等距张量叠片承载信息，避免泛化 3D 装饰。
- 虚线应解释为训练专用、可选或放大关联，不默认所有容器虚线。
- 字号按最终论文宽度检查。1600 px 宽画布的标签可从 22–28 px 起，但高像素不能代替最终可读性。
- 使用位置、标签、线型辅助颜色分组，避免只靠红绿区分。
- 简单公式用可编辑文字；复杂公式转成轮廓时披露无法直接编辑公式文本。

常用方向包括：精密机制图（算子/token/旁路）、分层系统图（角色和子模块）、视觉编码器图（张量/尺度/放大框）。根据真实参考混合这些表达，不将它们固定成几套配色模板。
